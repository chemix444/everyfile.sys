README.TXT — How a flash drive holds every file ×

This is a recreation of PortalRunner's "infinite flash drive": a microcontroller that pretends to be a USB storage device. It can't use a normal file system, because real file systems map files to finite, non-overlapping memory addresses. Instead it speaks MTP (the Media Transfer Protocol your phone uses), where the device is free to answer "what's in this folder?" with anything it likes — including the same 4,900 folders, forever.

The trick: a file path is just a big number

Each level has 4,900 folders (a 70-character alphabet, two characters per name, so 70 × 70 combinations). Your path through the folders is read as one giant base-4,900 number, one digit per folder:

path /Qf/3x/aa/… → digits [2118, 263, 1, …] → one big integer

To turn that number into a file, it gets re-written in base 256, since every byte of a file has 256 possible values. One wrinkle: numbers can't start with leading zeros, but files absolutely can start with null bytes. The fix is an offset trick — every digit is shifted by one before conversion (bijective numeration), so every byte sequence, including ones full of zeros, has exactly one path and every path has exactly one file. No duplicates, no gaps.

bytes [0x48, 0x69] ("Hi") ⇄ integer 18,793 ⇄ folder digits [4, 3893] ⇄ path /AD/wj

That's also why LOCATE.EXE works: finding a file is just running the same conversion backwards. Nothing is searched and nothing is stored — the math is the index.

Why 4,900 folders and 2-character names?

File browsers choke past roughly 5,000 icons in one folder, and they also cap the total length of a path. So the design has to pack the most information into the shortest path while staying under ~5,000 entries per level. Brute-forcing the combinations of alphabet size and name length gives the optimum: a 70-symbol alphabet, two symbols per folder name. Not glamorous, but it wins.

What's simulated here vs. the real device

The real build runs C on a $10 AliExpress microcontroller with an SD slot, answering MTP requests over USB. This page simulates the same logic in your browser: the folder listings are generated on the fly, the address bar is the cipher, and the file viewer is the decryption. The 32-bit MTP object-ID limit and the path-length wall still exist on real hardware — here, your scroll wheel is the only limit.
